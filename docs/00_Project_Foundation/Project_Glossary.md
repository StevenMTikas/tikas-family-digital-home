# Project Glossary

## Purpose

A single reference for the terms and concepts defined throughout this project's documentation, so anyone (including future you) can look up what a term means without hunting through the document where it was first defined. This is a living document — expected to grow as new terms are introduced.

## Goals

- Give one place to check "what does this term actually mean in this project," rather than re-deriving it from context each time.
- Keep definitions short and point back to the source document for full detail, rather than duplicating entire sections here.

## User Stories

- As a developer (including future me), I want to quickly look up an unfamiliar term without searching through a dozen documents.
- As anyone reviewing this documentation, I want confidence that terms are used consistently across every document.

## Features (Glossary Entries)

### System & Architecture

- **Digital Home** — the overall product; Tikas Family Digital Home. See `Vision.md`.
- **Host** — the always-on computer (Dad's) running the application, database, and local AI model. See `System_Overview.md`.
- **Connector** — a lightweight agent on a non-host device (computer or phone) that scans designated folders and syncs metadata to the host on a schedule. "Connector = scanner, host = brain." See `System_Overview.md`, `File_Connector_Architecture.md`.
- **Standing Integration Connection** — a user-initiated, ongoing connection to an external service (e.g., Email, Weather) where the act of connecting is itself the consent — distinct from the AI-initiated outside-call approval flow. See `Security_Architecture.md`.

### AI Roles

- **Assistant** — the on-demand, conversational AI role; responds to direct requests. See `Assistant.md`.
- **Advisor** — the proactive AI role; generates suggestions rather than direct answers. See `Advisor.md`.
- **Guardian** — the background AI role; monitors system and family health on a schedule, with its own broad-but-limited permission role. See `Guardian.md`, `AI_Permissions.md`.
- **AI_Memory** — the AI's curated, per-user store of distilled facts (preferences, routines, relationships) used as its first, fastest layer of context. See `AI_Architecture.md`, `AI_Memory.md`.
- **AI_Suggestion** — a stored, actionable recommendation generated by Advisor or Guardian, with accept/dismiss/thumbs-down feedback. See `AI_Suggestions.md`.

### Security & Permissions

- **Outside-Call Approval** — the flow requiring explicit, per-action user approval before the AI sends or requests anything beyond the home network, showing exactly what's being sent. See `Security_Architecture.md`.
- **Sensitive-Data Gate** — an additional approval layer, beyond general outside-call approval, required before sensitive-flagged content can leave the home — never grantable to a minor's account. See `AI_Permissions.md`.
- **Super Admin** — the single, unconditional top-level role (Dad); full technical and family control. See `Authorization.md`.
- **Scoped Admin** — an Admin role with full control limited to specific child user(s) they're scoped to (e.g., Vee scoped to Malachi). See `Authorization.md`.
- **Basic User** — the default role for a family member; standard access to their own content and whatever else permissions allow. See `Authorization.md`.
- **Admin Scope** — the set of child user(s) a Scoped Admin has authority over. See `Authorization.md`.
- **Trusted Device** — a device explicitly added by an admin, required for login to even be possible on that device. See `Security_Architecture.md`, `Authentication.md`.
- **Folder Permissions (View / Edit / Delete)** — the granular, per-folder access model governing Documents and Family Knowledge; supports nesting with inheritance, overridable only by the Super Admin. See `Folder_Permissions.md`.

### Content Types

- **Family Knowledge** — the general-purpose "family safety deposit box" for contacts, medical info, home records, insurance, and similar. See `Family_Knowledge.md`.
- **Password Entry** — a structured, browser-manager-style credential record, kept separate from general Family Knowledge items. See `Family_Knowledge.md`.
- **Memory** — a story-like record that can be text-only, photo-only, document-only, or any combination — broader than a single Photo. See `Memory.md`.
- **is_sensitive** — a flag on content (Documents, Photos, Family Knowledge, Password Entries, AI_Memory) requiring the sensitive-data gate before it can leave the home. See `AI_Permissions.md`.

### Product Experience

- **Morning Briefing** — the default content shown on Dashboard open: today's events, tasks, suggestions, and notable items. See `Morning_Briefing.md`.
- **Dashboard** — the overall home screen and navigation hub, containing the Morning Briefing plus ongoing updates, quick actions, and weather. See `Dashboard.md`.
- **Family Dashboard** — the shared, family-wide view (everyone's day at a glance), accessible from an individual's Dashboard. See `Morning_Briefing.md`, `Dashboard.md`.

### Project & Process

- **MVP** — the initial, minimum viable version of the product being specified throughout this documentation, as distinct from a future "commercial" release to other families. See `07_Development/MVP.md`.
- **Cursor Project Rules** — the "constitution" governing every coding session; non-negotiable engineering and product rules. See `Cursor_Project_Rules.md`.
- **Core Principles** — the non-negotiable beliefs guiding what the product is allowed to become, distinct from Cursor Project Rules' focus on how code is written. See `Core_Principles.md`.
